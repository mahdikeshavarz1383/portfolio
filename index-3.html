#TS-001 resolved docker · networking

Containerized API couldn't reach MongoDB on the same VPS

The Node.js API container started fine but every DB call timed out, even though MongoDB was running and reachable from the host.

root cause

The container was using localhost to reach Mongo, which inside a container points to itself, not the host.

fix

Put both services on the same user-defined Docker network and referenced Mongo by its container name instead of localhost.

#TS-002 resolved vpn · filtering

WireGuard tunnel connected but dropped all traffic

Handshake succeeded, the interface came up, but no packets actually got through — connection looked healthy while being unusable.

root cause

ISP-level deep packet inspection was fingerprinting and throttling the WireGuard handshake pattern.

fix

Documented the failure mode and moved to a different approach rather than fighting DPI at the protocol level — sometimes the right fix is knowing when to stop.

#TS-003 resolved monitoring

Service outages were only noticed hours later

A background bot process would silently die and no one — including me — knew until a user complained.

fix

Set up Uptime Kuma with Telegram alerting so any downtime triggers an immediate notification instead of waiting for user reports.
